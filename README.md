# Track Coach

在线使用（手机和电脑浏览器都可以打开）：https://lixiangyu85-a11y.github.io/track-coach/

数据保存在当前浏览器里，设备和浏览器之间不会自动同步。换设备时请用应用内的导出/导入。

中长跑教练用的浏览器排课工具。界面为中文。录入运动员主项与最好成绩后，按 Jack Daniels VDOT 推算训练配速，编排跑课和素质课，再放到周历里看负荷提示。没有后端：数据只存在本机浏览器，可用 JSON 备份导入、导出。

**English.** Track Coach is a training planner for middle- and long-distance running coaches. It stores athlete profiles, estimates Daniels VDOT paces from a personal best, builds running sessions and strength work, and shows them on a weekly plan with load alerts. Data stays in the browser (`localStorage`), with JSON backup import and export. The UI is in Chinese.

仓库：<https://github.com/lixiangyu85-a11y/track-coach>

## 适合谁用

给中长跑、公路跑教练在浏览器里排课：田径场间歇、公路长课、针对弱项的素质课，以及一周的负荷检查。数据留在这一台浏览器里，适合教练在本机单独使用。

## 功能

顶栏六个页面：**主页**、**运动员**、**排课**、**素质**、**周计划**、**方法库**。顶栏同时显示当前运动员，以及保存状态和「保存 / 导出 / 导入」。

### 主页

- 按当前运动员汇总本周跑课、素质课、跑量和阶段主题。
- 本周一到周日的简表。落在 I 或 R 区的课（间歇、法特莱克、重复、冲刺）会标出来。
- 列出本周负荷提醒（见下文），并提供进入各页面的入口。
- 可在名单里切换当前运动员。

### 运动员档案

- 姓名、可选性别（男子 / 女子）、主项、最好成绩、备注。
- 主项：800 米、1500 米、3000 米、5000 米、10000 米、障碍、半程马拉松、马拉松。
- 成绩可写成 `1:46`、`1:46.34`、田径三项百分秒 `1:46:34`，或纯秒数。半马、全马、10000 米的三段时间按 `时:分:秒` 解析（如 `1:22:30`、`3:15:00`）。
- 用主项最好成绩计算 VDOT，并列出等价成绩（800 米到马拉松）。障碍不参与等价换算。选中运动员时会提示：马拉松推算对多数业余选手往往偏快。
- 弱项在「素质」页标记，名单里会显示简称。
- 删除运动员会去掉其周计划；已保存的课时记录仍留在本地，只是不再挂在周表上。

### 排课

针对当前运动员搭建一堂跑课：

- 周期阶段：基础期、强化期、专项期、赛前减量、比赛周、恢复期。阶段会轻微平移各配速区的 %VDOT。
- 日期、场地（田径场、公路、越野/山地、力量房/室内、综合）、标题、主课要点。
- 热身、整理可用场地模板填入。整课都是 E 区（有氧轻松跑、长距离有氧）时，热身模板走轻松/恢复那一套；否则走质量课或速度课模板。
- 方法库里的课型：有氧轻松跑（E）、长距离有氧（E）、马拉松配速跑（M）、法特莱克跑（I）、变量跑（T）、节奏跑（T）、乳酸阈跑（T）、间歇跑（I）、重复跑（R）、冲刺/加速跑（R）。长距离和马拉松配速标为公路向。
- 每个模块是「组 ×（次数 × 距离）」，目标时间取该区配速中值。组间、次间休息可以是时间，也可以是慢跑距离。
- 组合课模板可一次加入多段距离（上/下阶梯、金字塔、混合、递快、专项分解，例如 200+400+600）。也可以自选距离拼一段。
- 页面上显示当前阶段的 E / M / T / I / R 配速（秒/公里）。
- 新建课时时，可以把同一课同步给其他运动员：距离、组次和休息方式保留，目标配速和按比例计算的间歇时间按各自 VDOT 重算。编辑已有课时时只更新当前这一课。

### 素质

七个弱项模块，每项带常见表现、建议频率和动作（组数、次数、要点）：

- 脚踝 / 足内在肌
- 小腿跟腱
- 大腿前侧
- 大腿后侧
- 臀髋
- 核心
- 单腿稳定

先在档案上标记弱项，再勾选本次针对的模块和动作，保存为一堂素质课。动作的组数、次数和要点可以改。

### 周计划

- 填写周起始、本周阶段和主题，再勾选已有跑课和素质课。打开页面时周起始是本周一；日历从所选日期起连续排 7 天，并按顺序标成周一到周日，所以这里应选周一。
- 日历按周一到周日列出当天的跑课和素质课；点课时可回到排课或素质页编辑。高强课（含 I 或 R）会标出。
- 周期骨架只生成阶段和主题文字，不自动创建课时。模板有三个：「4 周强化块」「6 周赛前块」「8 周一般准备」。套用时会覆盖这些周已保存的阶段和主题，已勾选的课时保留。
- 单课或整周可以复制成纯文本；剪贴板不可用时改为下载 `.txt`。跑课和素质课也可以打开打印页。
- 课后打卡：是否完成、完成情况、实际配速或感受、RPE（1–10）。同一课时再次打卡会覆盖上一条记录。

#### 负荷提示

提示分三级：正常、留意、偏高。质量课指含 M / T / I / R 区块的课；有氧轻松跑和长距离（E）计入周跑量和有氧公里，不计入质量课次数。高强课指含 I 或 R 的课。

周计划按**已经勾进这一周**的课计算。主页按**日期落在本周一到周日**的课计算，和有没有勾进周计划无关。两边用的是同一套规则。

各阶段的质量课次数、高强课次数、质量课公里上限：

| 阶段 | 质量课次数 | 高强课（I/R）次数 | 质量课公里 |
| --- | --- | --- | --- |
| 基础期 | 3 | 1 | 12 |
| 强化期 | 4 | 2 | 18 |
| 专项期 | 4 | 2 | 16 |
| 赛前减量 | 3 | 2 | 10 |
| 比赛周 | 2 | 1 | 6 |
| 恢复期 | 2 | 0 | 8 |

VDOT 会缩放上表里的质量课公里：低于 40 时约为 0.85 倍；达到 40、不到 50 时不缩放；达到 50、不到 60 时约为 1.1 倍；达到 60 时约为 1.2 倍，并把质量课次数上限加 1。质量课次数达到上限为「留意」，超过为「偏高」。高强课次数超过上限为「偏高」。质量公里超过上限的 85% 为「留意」，超过上限为「偏高」。负荷提示里，赛前减量写成「赛前」。

另外会检查下面几项。和上一周比较时，上一周的跑量和最长一课按课时日期落在前 7 天计算：

- **Daniels 强度占比**（相对本周跑量）：T 不超过约 10%，I 不超过约 8%，R 不超过约 5%。超过为「留意」，超过建议值的 1.2 倍为「偏高」。
- **单次间歇**：I 区单次距离超过约 1.2 km，或单次时间超过约 5 分钟（用已填目标时间；目标时间为 0 时按 I 区配速估算），标为「留意」。
- **周跑量增幅**：上周跑量至少 8 km 时，本周增幅超过约 10% 为「留意」，达到或超过约 20% 为「偏高」。
- **长课增幅**：上周最长一课至少 8 km 时，本周最长一课多出约 3 km 以上为「留意」。
- **连续未减载**：基础 / 强化 / 专项连续满 3 周为「留意」，满 4 周为「偏高」。恢复期、赛前、比赛周会把这段连续计数清零。
- **高强课间隔**：两堂 I/R 课间隔不足 48 小时为「偏高」。
- **素质与高强同日**：同一天既有素质课又有高强跑课，为「留意」。
- 周计划页额外提示：本周素质课达到 4 次；档案已标弱项但本周没有素质课。

这些是排课时的参考提示，不会阻止保存。

### 方法库

只读对照：各跑课方法的配速区、常用距离和默认结构；E/M/T/I/R 对应的 %VDOT（E 59–74、M 75–84、T 83–88、I 95–100、R 105–110）；组合课模板；素质弱项模块。

## 数据存在哪里

所有数据在浏览器 `localStorage`，键名 `track-coach:v2`。写入的是一个 JSON 信封：`version`（当前为 2）、`savedAt`、`state`。`state` 里有运动员、跑课、素质课、周计划、打卡记录和当前运动员。

- 修改后约 400 毫秒自动保存。顶栏在保存完成前显示「未保存…」，也可以按「保存」立刻写入。
- 若只存在旧键 `track-coach:v1`，打开页面时会迁到 v2 并删掉旧键。
- 「导出」下载 `track-coach-backup-YYYY-MM-DD.json`，内容与本地存储的信封相同。
- 「导入」读取该 JSON（或同一形状、把 `state` 放在顶层的 JSON），**整份替换**当前数据并立即保存。文件不是合法 JSON 时页面提示失败，原数据保留。合法 JSON 但字段对不上时，缺的列表会按空数据处理，所以导入前最好先导出一份当前备份。
- 清除站点数据、换浏览器或换设备后，未导出的内容就没有了。换电脑前先导出备份。

周计划里的「复制 / 导出本周 / 打印」是给人看的文本或打印页，不是完整备份。要搬走全部数据，用顶栏的 JSON 导出。

## 技术栈

- [Vite](https://vite.dev/) 8、React 19、TypeScript
- 检查：oxlint（`npm run lint`）
- 测试：Vitest（`npm test`），覆盖 VDOT、成绩时间解析、负荷上限缩放、高强课冲突和周负荷提示
- 界面样式写在项目自己的 CSS 里。配速、负荷和存储都在浏览器里完成。

## 环境要求

- Node.js：当前锁定的 Vite 8.3.5 要求 `^20.19.0` 或 `>=22.12.0`
- npm（使用仓库里的 `package-lock.json`）

## 本地运行

```bash
npm install
npm run dev
```

开发服务器地址以终端输出为准（Vite 默认是 <http://127.0.0.1:5173/>）。

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动 Vite 开发服务器 |
| `npm run build` | `tsc -b` 类型检查后执行 `vite build`，产物在 `dist/` |
| `npm run preview` | 本地预览构建结果 |
| `npm run lint` | 用 oxlint 检查 |
| `npm test` | 跑一遍 Vitest |
| `npm run test:watch` | Vitest 监听模式 |
